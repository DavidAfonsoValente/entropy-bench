\begin{abstract}
Base models are chosen for fine-tuning by their benchmark scores. We test a label-free alternative:
score each candidate's bits per byte on whole documents of fresh, unlabelled text from the target
domain. For fifteen base models fine-tuned on a news-writing task, this ranking places every model
within one rank of where it finishes and orders $37$ of $39$ size-matched pairs as the fine-tuned
systems do. GSM8K and MMLU-Pro order the same pairs at chance, and so do the models' own scores on
the task before any training: fine-tuning reorders the models, and the document reading predicts
the order they end in. HellaSwag orders $34$. Two details decide the result. The text must come
from the task's domain, or close to it: the same measurement on arXiv mathematics orders $23$ of
the $39$ pairs. And each document must be read whole, from its beginning: scored on fixed-length
blocks cut from concatenated text, as perplexity is often computed, the ranking puts the model
that fine-tunes best thirteenth of fifteen. Read this way, the measurement needs no labels, no
task and no training, and adapting the models to the domain first barely changes it. Which
benchmark the ranking resembles follows the text: HellaSwag on general prose, GSM8K and MMLU-Pro
on mathematics. \ifanon Code and artifacts are provided as
supplementary material.\else Code and artifacts: \repolink{}.\fi
\end{abstract}

\section{Introduction}
\label{sec:intro}
An engineer choosing a base model for a product usually has plenty of text from the product's
domain and a shortlist of open checkpoints, and the model they pick will be fine-tuned before it
ships. Fine-tuning every candidate would settle the choice, but it needs a task definition,
labelled data and a training run per model. So the choice is made from benchmark tables. Model
reports compare base models on MMLU-Pro \citep{wang2024mmlupro}, GSM8K \citep{cobbe2021gsm8k},
HellaSwag \citep{zellers2019hellaswag} and similar suites \citep{yang2024qwen25}, and the Open LLM
Leaderboard ranks pretrained models on six benchmarks \citep{fourrier2024leaderboard}.

We find that the fine-tuned ranking can be read off before any task exists, from unlabelled text
alone. For each candidate we compute its loss in bits per byte (BPB) on whole documents of fresh
text from the domain, each document read from its own beginning. On a news-writing task, this
ranking places all fifteen fine-tuned models within one rank of where they finish
(Figure~\ref{fig:headline}). GSM8K and MMLU-Pro misjudge several of the same models, and order
size-matched pairs of them at chance. So do the models' own scores on the task before any
training: fine-tuning reorders the models, and the document reading predicts the order they end in.

That held-out loss predicts fine-tuning is not the received view. The most direct test we know of
fine-tunes fifty 1B models and finds that perplexity on a general held-out set orders pairs of the
fine-tuned systems worse than chance, while few-shot accuracy on the task does best
\citep{zeng2025indicators}. Besides the cohort, two details separate that measurement from ours,
and each is often got wrong.

The first is which text. When we score the same fifteen models on arXiv mathematics instead of news,
the ranking orders only $23$ of $39$ size-matched pairs as the news fine-tune does, against $37$
with news text, and falls below ranking by model size (Section~\ref{sec:owntext}). Which benchmark
the ranking agrees with follows the text too. On news, Reddit and Hacker News it agrees with
HellaSwag; on mathematics it agrees more with GSM8K and MMLU-Pro.

The second is how the text is cut. A common convention joins the test set into one stream and
scores fixed-length blocks cut from it \citep{hfperplexity}, so most blocks begin mid-document.
Scored that way, the same news text misranks several strong models, and Gemma-4-12B, which builds
the best fine-tuned system of the fifteen, comes thirteenth (Section~\ref{sec:mechanism}). Reading
each document from its own start fixes this with no training. Adapting every model briefly to the
domain repairs the block reading as well, which is how we found the problem, but on whole documents
it changes almost nothing (Section~\ref{sec:noadapt}).

Loss is a natural measure for this choice. A base model acquires its capabilities by minimising
cross-entropy on text, and fine-tuning minimises it again on the task. Cross-entropy is also a
strictly proper scoring rule \citep{gneiting2007scoring}. If $p$ is the distribution that generated
the domain's text and $q$ is a model, the model's expected loss is
\begin{equation}
H(p,q) = H(p) + \mathrm{KL}(p\,\|\,q),
\label{eq:ce}
\end{equation}
where $H(p)$, the entropy of the text, is the same for every model \citep{cover2006elements}. The
difference between two models' held-out losses therefore estimates the difference in how far each is
from the domain's text. Whether that predicts usefulness on a task is an empirical question, which
Section~\ref{sec:divergence} tests. We count the loss per byte, because each model has its own
tokenizer but they all read the same bytes, and we compute it on fresh text: Reddit, Hacker News
and arXiv were collected after every candidate was released, and the news snapshot, which predates
some releases, is screened for membership (Section~\ref{sec:protocol}). Benchmarks offer neither
guarantee: vendors optimise for the ones they report, and their questions can leak into
pre-training data.

We evaluate seventeen base models from 0.5B to 35B parameters. Fifteen are fine-tuned on the news
task, writing an article's opening paragraph from its body, and eleven are scored on all four
corpora under the block readings too (Table~\ref{tab:cohort}). Our main findings are:
\begin{itemize}[leftmargin=1.2em,itemsep=2pt,topsep=3pt]
\item \textbf{BPB on whole documents of the domain's text anticipates the fine-tuned ranking.} It
orders $37$ of $39$ size-matched pairs as the fine-tuned systems do and places every model within one
rank of its finish. HellaSwag orders $34$; GSM8K, MMLU-Pro and the models' own untrained scores on
the task are at chance (Section~\ref{sec:divergence}).
\item \textbf{Blocks cut from a stream misrank strong models.} Scored on fixed-length blocks,
Gemma-4-12B falls from second to thirteenth, and the ranking orders $30$ of the $39$ pairs
(Section~\ref{sec:mechanism}).
\item \textbf{No training is needed.} Adapting every model to the domain before reading the
documents lowers each model's loss but barely changes the order, on all four corpora
(Section~\ref{sec:noadapt}).
\item \textbf{The text has to be like the task's.} Reddit text orders $34$ of the $39$ news pairs,
Hacker News $31$ and mathematics $23$.
Across corpora, the ranking agrees with HellaSwag on general text and with GSM8K and MMLU-Pro on
mathematics (Section~\ref{sec:owntext}).
\end{itemize}
The measurement is deterministic: re-running it reproduces every model's BPB exactly
(Section~\ref{sec:stability}).

\section{Related Work}
\label{sec:related}
\textbf{How base models are chosen.} Base models are released and compared through benchmark
tables. The Qwen-2.5 report, for one, compares its base models with others on MMLU, MMLU-Pro, GSM8K,
HellaSwag and a dozen more benchmarks \citep{yang2024qwen25}, and the Open LLM Leaderboard ranks
pretrained models on six benchmarks, MMLU-Pro and MATH among them \citep{fourrier2024leaderboard}.
Whether these scores say which base model will be best once fine-tuned is rarely tested. The closest
test is that of Zeng et al.\ \citep{zeng2025indicators}, who fine-tune fifty 1B models pre-trained with varied objectives and data
and find that perplexity on the Pile development set orders pairs of the fine-tuned systems worse
than chance (pairwise accuracy $0.33$--$0.38$); among their unsupervised indicators, few-shot
accuracy on the target task does best. The
received view is therefore that loss does not predict fine-tuning. We measure loss on the target
domain's own text, across families and sizes, and it predicts the fine-tuned order closely; text
from another domain predicts it less well (Section~\ref{sec:owntext}).

\textbf{Loss, compression and capability.} Language modelling was grounded in the entropy of text
from the start \citep{shannon1951prediction}. Token-level perplexity depends on each model's
vocabulary \citep{mielke2019perplexity,ahia2023languages}; normalising by UTF-8 bytes restores a
common unit \citep{gao2021pile,magnusson2023paloma}, and loss-based metrics carry more signal and
less noise than accuracy across hundreds of models \citep{heineman2025signal}. Language modelling
is equivalent to compression \citep{deletang2024compression}, and compression of fresh text
correlates linearly with benchmark scores across about thirty models
\citep{huang2024compression}. UncheatableEval \citep{uncheatableeval} maintains a leaderboard of
compression on recently published text for the same reason we use fresh text. These works check
loss against benchmarks; we check it against fine-tuned systems, and find it predicts them at least
as well as the closest benchmark and far better than GSM8K and MMLU-Pro.

\textbf{How loss is computed.} The Hugging Face guide to perplexity joins a test set into one stream
and scores it with a sliding window \citep{hfperplexity}; lm-evaluation-harness scores each document
separately, from a beginning-of-sequence token \citep{gao2024lmeval}. Both are in common use, and
the choice is treated as a detail. We show that it reorders models, and which choice predicts fine-tuning.

\textbf{Choosing a model to fine-tune.} Lin et al.\ predict which LLM will fine-tune best by fitting
a rectified scaling law to small fine-tuning runs on the target task \citep{lin2024rectified}; this
needs task data and training, where our measurement needs neither. Transferability estimators such
as LEEP and LogME \citep{nguyen2020leep,you2021logme} score a pre-trained model from its features on
labelled target data. Train-before-test \citep{zhang2025trainbeforetest} gives 61 models identical
supervised preparation across 24 tasks and raises cross-benchmark agreement. Observational scaling
laws relate benchmark performance across model families to a few capability measures
\citep{ruan2024observational}, and loss predicts downstream error within controlled families
\citep{gadre2025scales}. Thrush et al.\ use the varying correlation between per-domain perplexity
and benchmark scores to select pre-training data \citep{thrush2024perplexity}. Domain-adaptive
pre-training \citep{gururangan2020dapt} and dynamic evaluation \citep{krause2018dynamic} adapt a
model before measuring it; for ranking, we find this unnecessary once documents are read whole.

\textbf{Contamination.} Models memorise duplicated pre-training text
\citep{carlini2021extracting,carlini2023quantifying}, so deduplication and contamination analysis
matter \citep{lee2022deduplicating,xu2024survey}. Reference-free membership signals
\citep{shi2024mink,zhang2025minkpp} are weak for large language models
\citep{duan2024mia}, which is why our main protection is the date of the text and the screens serve
only for conservative removal. Fresh benchmarks such as LiveBench \citep{white2025livebench} apply
the same idea to labelled questions.

\section{Method}
\label{sec:protocol}
The method has three phases (Figure~\ref{fig:protocol}). The corpus is collected and screened
before any model is run on it, every candidate then reads the held-out documents whole, and its
loss is counted in bits per byte. There is no training and no label at any point.

\paragraph{Phase 1: a decontaminated corpus.} The evaluation text must be text that no candidate
has seen, and we use three safeguards for this. \emph{Time:} Reddit and Hacker News were scraped in
August 2026, after every model in the cohort was released, and the arXiv titles and abstracts were
posted between 9 June and 20 August, after most of the releases. \emph{Hygiene:} we remove exact
duplicates, text that fails the Gopher quality heuristics \citep{rae2021gopher} and MinHash/LSH
near-duplicates \citep{broder1997resemblance} at Jaccard $0.60$. The 80/10/10 split shares no
identifier or normalised text across splits. \emph{Membership screens:} the news snapshot (Google
News, 8 June 2026, $119{,}054$ articles) predates some of the releases, so we also test every model
for having seen it. Min-K\%++ \citep{zhang2025minkpp} flags passages whose least likely tokens are
unusually likely for the model, and a context-sensitivity test flags passages whose loss drops more
than expected when the model is shown other text from the same corpus. We remove every passage
flagged for any model, $80$ in total, so all candidates are measured on the same corpus
(Appendix~\ref{app:robust}). The corpora, their manifests and record fingerprints are
released.\artifact{docs/DATASET.md}

\paragraph{Phase 2: whole documents.} Each test document is read on its own, starting from its
tokenizer's beginning-of-document token, if it adds one, with up to $2{,}048$ tokens of
context. A document longer than that is read in overlapping windows with a stride of $1{,}024$, and
each token is scored once. The beginning-of-document token is
never scored. On each corpus every model reads the same test documents, up to $6.0$\,MB, so the
text is identical byte for byte. The implementation is
released.\artifact{lm_adapt_bench/evaluate.py} The per-model scores are
released with the analysis that turns them into the numbers below.\artifact{results/doc_protocol_cells}

\paragraph{Phase 3: bits per byte.} Let $\loss$ be the total cross-entropy, in nats, over the
scored tokens of the test text, and $|B|$ the UTF-8 byte length of the text those tokens cover:
\begin{equation}
\bpb = \frac{\loss}{|B| \ln 2}.
\label{eq:bpb}
\end{equation}
A model with a larger vocabulary predicts fewer, longer tokens; dividing by bytes rather than tokens
removes the penalty per-token perplexity would give it.

\section{Experimental Setup}
\label{sec:setup}
\paragraph{Models.} Eleven base checkpoints between 0.5B and 35B parameters are evaluated on all
four corpora, on blocks as well as whole documents (Table~\ref{tab:cohort}). Most are dense Transformers; one is a sparse
mixture-of-experts, and LiquidAI's LFM2.5-1.2B is a hybrid of convolution and attention blocks. On
news and on arXiv mathematics we add six more models, chosen before they were run to fill gaps in model size and
to add publishers, for 17 in total (Table~\ref{tab:cohort}); their whole documents are also
scored on Reddit and Hacker News. They come from the Llama, Qwen, Gemma,
Ministral, Mistral-NeMo, Falcon, SmolLM and LFM families
\citep{dubey2024llama3,meta2024llama32,yang2024qwen25,qwen2026qwen35,gemma2026gemma4,liu2026ministral3,mistral2024nemo,tii2024falcon3,benallal2025smollm2,liquid2026lfm25}.
Eight of the seventeen are Qwen models.

\paragraph{Corpora.} We use four corpora: news, Reddit, Hacker News and arXiv mathematics.
Table~\ref{tab:corpora} gives their sizes and how each was screened.

\paragraph{Benchmarks.} For comparison, we score every model on MMLU-Pro (a stratified
$1{,}000$-question subset, so one question is $0.1$ points), HellaSwag (all $10{,}042$ validation
items) and GSM8K (all $1{,}319$ test items) with \emph{lm-evaluation-harness} 0.4.12
\citep{gao2024lmeval}, on one machine with one software build, following the protocol in
Appendix~\ref{app:rescore}. We use scores we measured ourselves, not the values reported on model
cards, and we publish the harness logs.

\paragraph{The fine-tuning task.} We fine-tune fifteen of the seventeen models
(Table~\ref{tab:cohort}), each starting from its base weights, to write an article's opening
paragraph, its lede, from the rest of the article. Gemma-4-31B and Qwen-3.5-35B-MoE are left out
because the fine-tune's $1{,}280$-token sequences and generation pass do not fit them on one GPU.
All fifteen use one shared LoRA recipe (Appendix~\ref{sec:downstream}) and are scored by ROUGE-L, an F-measure based
on the longest common subsequence with the reference \citep{lin2004rouge}, on $500$ held-out
articles that are not part of the BPB test set. The pairs to compare and the statistic were fixed
in code before the fine-tuning jobs ran (Appendix~\ref{sec:downstream}). We chose this task because
every article provides its own reference, the lede written by the journalist, so no annotation is
needed, and writing a good lede requires reading the whole article and writing in the style of the
domain.

\paragraph{Statistics.} We compare rankings mainly by \emph{pairwise accuracy}, the fraction of
model pairs that a ranking orders in the same way as a reference. Pairwise accuracy counts only
\emph{size-matched} pairs, two models whose parameter counts differ by less than a factor of two;
when one model is more than twice the size of the other, the larger one usually wins, and a ranking
would get the pair right by following size. Because pairs that share a model are not independent,
$95\%$ intervals come from a cluster bootstrap over models ($20{,}000$ draws). Intervals for a single
fine-tuned pair resample its $500$ evaluation articles. With fifteen models the intervals are wide,
and we say so where it matters.

\section{Results}
\label{sec:results}

\subsection{BPB on the domain's documents anticipates the fine-tuned ranking}
\label{sec:divergence}
A team will fine-tune whichever model it chooses, so the question is whether a measurement taken
before any task exists can say how that fine-tuning will turn out.
\begin{figure}[t]
\centering
\includegraphics[width=\textwidth]{figures/fig_downstream.pdf}
\caption{\textbf{How well does each ranking predict the fine-tuned results?} Each point is a pair
of fine-tuned models whose parameter counts are within a factor of two ($39$ pairs; $38$ for GSM8K,
where two models tie). For each pair, $x$ is how strongly the ranking prefers one model (the gap in
that measure) and $y$ is how much better that model's fine-tuned system scores in ROUGE-L. Points
above the line are pairs the ranking orders correctly. Filled markers are \emph{resolved} pairs,
whose ROUGE-L difference has a $95\%$ bootstrap interval over the $500$ articles that excludes zero.
BPB on whole documents gets $37$ of $39$ pairs right, including $21$ of the $22$ resolved pairs;
HellaSwag gets $34$; GSM8K gets $18$ of $38$, and all eleven of its pairs with gaps between $15$ and
$25$ points fall below the line.}
\label{fig:downstream}
\end{figure}
Measured with no task, no labels and no training, BPB on whole news documents orders $37$ of the
$39$ size-matched pairs ($0.949$, $95\%$ interval $[0.817, 1.000]$) in the same way as the
fine-tuned systems, and $21$ of the $22$ pairs that the fine-tuning results themselves resolve
(Figure~\ref{fig:downstream}, Table~\ref{tab:downstream}). HellaSwag orders $34$ ($0.872$,
$[0.640, 1.000]$); the difference, $+0.077$ $[0.000, 0.300]$, does not separate the two. GSM8K and
MMLU-Pro are at chance, with $0.474$ and $0.513$. So is the strongest label-free baseline, the
models' own scores on the task before any training (the few-shot baseline that Zeng et al.\ found
best): it orders $20$ of the $39$ pairs and agrees with the fine-tuned order at Spearman $0.53$.
Fine-tuning reorders the models, and the document reading predicts the order they end in. Ranking
by size agrees with the finish at Spearman $0.92$ over the fifteen, because large models beat
small ones, but orders $28$ of the $39$ size-matched pairs; BPB beats it by $+0.231$ in pairwise
accuracy $[+0.059, +0.452]$. Over all fifteen models the document ranking agrees with the final
order at Spearman $0.99$: every model is within one rank of its final position, and eleven are
exactly in place. GSM8K reaches $0.59$, MMLU-Pro $0.71$ and HellaSwag $0.97$. On the $32$ pairs
whose models come from different publishers, document BPB orders $30$ and HellaSwag $27$.

Table~\ref{tab:outofbox} shows the models the benchmarks misjudge most. Gemma-4-12B, ninth on GSM8K
and eighth on MMLU-Pro among the fifteen, produces the best fine-tuned system; in the pair fixed in
advance it beats Ministral-3-14B by $+0.018$ ROUGE-L $[+0.011, +0.025]$. The $55.3$-point GSM8K gap
between Llama-3.2-1B and Qwen-2.5-1.5B did not separate their fine-tuned systems: that pair was
inconclusive. Every model improved on its own base weights and beat the score of copying the
article's first body sentence (ROUGE-L $0.125$).

The prediction does not depend on the fine-tuning recipe. With a deliberately different recipe,
recipe B (LoRA rank $64$ and $\alpha{=}128$, three times the learning rate, half the batch size, $400$
steps and a new seed), the order of the fine-tuned systems hardly changes (Spearman $0.982$), and
document BPB is still the best predictor at $0.923$, ordering correctly all $20$ pairs that recipe B
separates; its margin over size no longer resolves ($+0.179$ $[-0.036, +0.441]$).

\subsection{Blocks cut from a stream misrank strong models}
\label{sec:mechanism}
The same news text, scored the common way, gives a different ranking. Cut into non-overlapping
$512$-token blocks from the concatenated test set, each block read with no earlier context, it
orders $30$ of the $39$ pairs ($0.769$) and agrees with the fine-tuned order at Spearman only $0.71$.
Gemma-4-12B, second on whole documents, is thirteenth of fifteen on blocks, behind models with
fewer than $2$B parameters, and LFM2.5-1.2B is last (Table~\ref{tab:outofbox}).

Figure~\ref{fig:blockpos} shows why. Gemma-4-12B starts a block at $2.83$ bits per byte, while
Qwen-2.5-1.5B, eight times smaller, starts at $2.04$. Gemma stays behind for most of the block and
is ahead by the end, $0.72$ against $0.77$. The early positions have the highest loss, so they
contribute most of the difference between the two block averages. Blocks are cut from a packed
stream, so most start in the middle of a document, without the beginning-of-document token that
models such as Gemma are trained to see first.

Two tests, with their decision rules fixed before they ran, point at the cut rather than the model.
Scoring
only positions $64$, $128$ or $256$ onwards of each block removes the first tokens of the block but
not the mid-document start, and on the $10$ size-matched fine-tuned pairs whose models we scored
this way it leaves the block reading at $6$ correct, unchanged. Reading every test document whole,
from its own start, ranks the fifteen models as in Section~\ref{sec:divergence}, and Gemma-4-12B
moves from thirteenth to second. The document reading is how lm-evaluation-harness scores text,
with no parameter to tune; we added it after the fine-tuning results were known, with its rule
fixed before it ran. We did not separate the beginning-of-document token, the document boundary
and the longer context; together, they amount to reading the text as the model was trained to see
it.

\subsection{No training is needed}
\label{sec:noadapt}
Adapting every model briefly to the domain before scoring it is a natural precaution, and on blocks
it is a repair: adapted block BPB ranks the fifteen models exactly as whole documents do, because
the models that gain most from adaptation are the ones blocks misrank (Appendix~\ref{app:readings}).
On whole documents it changes little. Adapting each model with the same recipe and then reading
the documents lowers every model's news loss, by $2.0$--$7.9\%$, but the two document rankings agree
at Spearman $0.993$: two neighbouring pairs swap. In the one that is size-matched, Gemma-4-12B,
which gains the most, moves past Mistral-Nemo-12B into first place; the adapted documents order
$38$ of the $39$ pairs, one more than the unadapted reading, inside the same interval. The same holds on the other corpora: for the eleven
original models, the adapted and unadapted document rankings agree at Spearman $0.982$
on Reddit, on Hacker News and on arXiv mathematics, with adaptation lowering loss by $1.9$--$11.2\%$.
We fixed the threshold for this claim, $0.95$, before the adapted runs.

\subsection{The text has to be like the task's}
\label{sec:owntext}
The document reading predicts the news fine-tune when it reads news. Reading arXiv mathematics
instead, the same fifteen models are ordered correctly on $23$ of the $39$ pairs ($0.590$,
$[0.260, 0.929]$) and on $12$ of the $22$ resolved pairs, below ranking by model size
(Table~\ref{tab:downstream}). Text close to news does better. Reddit and Hacker News are general
prose like news, and on the same fifteen models Reddit orders $34$ of the $39$ pairs ($0.872$,
$[0.659, 1.000]$) and Hacker News $31$ ($0.795$, $[0.481, 1.000]$). The order is news $37$, Reddit

\subsection{The measurement is deterministic}
\label{sec:stability}
The document reading involves no randomness: the adapted jobs re-read every unadapted model and
reproduced its document BPB exactly, and the control models reproduce the published unadapted block
readings on a second host to within $0.04\%$.

BPB has a structural advantage over generative benchmarks here. Floating-point addition is not
associative, so results on a GPU can change with batch size and kernel choice
\citep{he2025nondeterminism}. A generative benchmark decodes greedily, so a tiny change in two
nearly tied logits can flip a token, and the model then continues from its own changed output.
BPB is computed with teacher forcing: every prediction is conditioned on the true text, so a small
perturbation changes one log-probability slightly and does not propagate. Generative scores are
also sensitive to decoding settings that BPB does not use: dropping a single decoding setting
shipped with Gemma-4-12B changed its GSM8K score by $9.86$ points and its MMLU-Pro score by $14.30$
(Appendix~\ref{app:rescore}).

\section{Limitations}
\label{sec:limits}
The fine-tuned evidence is one task, lede writing in news, with two LoRA recipes at a small fixed
budget and fifteen models, seven of them Qwen, so the intervals are wide and BPB and HellaSwag are
not separated. We piloted
two fine-tuning tasks on arXiv mathematics, writing a title from its abstract and the reverse; on
both, a 0.5B and a 12B model finished within $0.012$ ROUGE-L of each other, so by a rule fixed in
advance neither task could rank models and neither was run further. The two largest models were not
fine-tuned. Membership screens cannot prove that a proprietary training set excludes a text; the
dates of the Reddit, Hacker News and arXiv corpora are the stronger guarantee.

\section{Conclusion}
\label{sec:using}
Base models are chosen by benchmark scores, but those scores grade abilities the task may not use. We ranked candidates instead by their loss, in bits per byte, on fresh text from the
target domain, with each document read whole from its own start. It needs no labels, no task
definition and no training, only a forward pass over a few megabytes of text.

On a news-writing task this ranking placed all fifteen fine-tuned systems within one rank of where
they finished and ordered $37$ of $39$ size-matched pairs correctly. GSM8K and MMLU-Pro were at
chance, as were the models' own scores on the task before training; HellaSwag ordered $34$. Two choices decide whether the measurement works. Text from
another domain, arXiv mathematics, ordered only $23$ of the pairs. Text cut into fixed-length blocks
put Gemma-4-12B, the model that fine-tunes best, thirteenth of fifteen. With the domain's own
documents read whole, adapting the models first changed almost nothing. A new corpus can be
collected for every domain and every evaluation, so the text the measurement reads stays unseen.

\section{The Block and Adapted Readings}
\label{app:readings}
Sections~\ref{sec:mechanism} and~\ref{sec:noadapt} compare the document reading with these.

\paragraph{Blocks, unadapted and adapted.} Every candidate is adapted to the retained training text,
packed into contiguous $512$-token blocks, using LoRA \citep{hu2022lora} on all linear layers, and
then scored on non-overlapping $512$-token test blocks cut from the packed test stream, each read
with no earlier context. Beginning-of-document tokens inside a block are used as context but never
scored. Because blocks are cut in tokens, each model covers a slightly different amount of text,
$5$--$10\%$ apart (Appendix~\ref{app:robust}). The same block reading without adaptation is the
\emph{unadapted block} reading. For adaptation, each candidate can get its own hyperparameter search with Optuna \citep{akiba2019optuna}.
A Tree-structured Parzen Estimator (TPE; \citealp{bergstra2011tpe}) proposes the learning rate,
batch size, warm-up, weight decay, LoRA rank, $\alpha$ and dropout; successive halving
\citep{jamieson2016successive} prunes weak trials from $50$ steps on; and every trial is scored by
BPB on the validation split, never on the test split. Every model gets the same number of trials
and no time limit, because with a wall-clock limit small models complete more trials than large
ones and end up better tuned (Appendix~\ref{app:robust}). The best configuration is then trained
until validation BPB stops improving. The released pipeline implements this
procedure.\artifact{lm_adapt_bench} Every
adapted number in this paper uses a single shared configuration instead, for compute reasons,
described next. Adapted models can also read whole documents (Section~\ref{sec:noadapt}).

\paragraph{Adaptation runs.} Because of limited compute, all runs reported here use one shared
configuration instead of the per-model search: LoRA rank 16, $\alpha{=}32$, dropout $0.05$, learning
rate $10^{-4}$, effective batch size 32 and $250$ update steps, a common LoRA setting. The runs are a
fixed budget, not trained to convergence. This is $4.1$M training tokens per candidate and costs
$3.7$ GPU-minutes on one A100 at $0.5$B parameters, $11.6$ at $7.7$B, $24.7$ at $12$B and $62.7$ at
$31$B; at $512$ tokens per sequence every model's adaptation fits on one 64\,GB GPU. The budget is
matched in tokens, so models with larger vocabularies see a few percent more bytes of text.

\paragraph{What adaptation does to the block reading.} For the eleven models, the block rankings
before and after adaptation have a Spearman correlation of only $0.655$ on news, $0.609$ on Reddit
and $0.682$ on Hacker News, and one model moves seven places (Table~\ref{tab:ranks}). The changes are
uneven. On news, adaptation lowers block loss by $3.6$--$5.4\%$ for every Qwen, Llama and Ministral
model, but by $17.0\%$ for Gemma-4-31B, $24.5\%$ for Gemma-4-12B and $36.4\%$ for LFM2.5-1.2B. These
three are the only models that move up, and they are the models the block reading misranks. For the
fifteen fine-tuned models, adapted block BPB ranks them exactly as the unadapted document reading
does (Spearman $1.00$). Most of what adaptation did to the block reading was teaching the models to
read text that starts mid-document.

\paragraph{Why the search gives every model the same number of trials.} The per-model search (Appendix~\ref{app:readings}) uses
a multivariate TPE sampler (seed $42$) over learning rate ($10^{-6}$--$10^{-3}$, log), physical batch
($2$, $4$, $8$), gradient accumulation ($1$--$16$), warm-up ratio ($0$--$0.2$), weight decay
($10^{-5}$--$10^{-1}$, log), LoRA rank ($8$--$64$), $\alpha$ as a multiple of rank ($1$, $2$, $4$) and
dropout ($0$--$0.2$); a successive-halving pruner starts trials at $50$ steps and promotes the best
third at each rung; and the objective is BPB on a fixed $256$-block subset of the validation split.
An earlier run of this search on the eleven-model news cohort was capped by wall-clock time rather
than by trial count, and the cap was confounded with model size: the two largest models completed
four trials each while the 1B models completed 17 and 18 (\texttt{results/legacy\_sweep/*/trials.csv}),
and the five models of 9B or more all kept the same third draw of the seeded sampler as their winner.
A time-capped search hands small models a better-tuned adapter and biases the ranking by parameter
count, which is why the released pipeline budgets the search in trials and applies no time cap by
default. Apart from the right panel of Figure~\ref{fig:blockpos}, none of those adapters produces a
number in the paper.

\paragraph{Membership screens.} The news corpus passes three reference-free membership screens per
model: Min-K\%++ (normalised likelihood of the lowest-probability $K{=}20\%$ target tokens),
context sensitivity (target loss with and without sampled same-corpus prefixes) and, for flagged
passages only, preference for the original passage over two word-swap perturbations. The union over
models and screens removed $80$ unique sequences, after which every model receives the identical
retained corpus. Near-$100\%$ preference for the original is expected from fluency alone, so we draw
no memorisation conclusion from the third test (\texttt{results/contamination/}).

\paragraph{Context length.} Varying the inference context on $64$ fixed held-out target windows from
$16$ to $2048$ tokens, both models measured improve with context and the larger improves faster, so
a protocol that scores only short contexts under-rates models that use long ones. Measured context
sensitivity is $0.032$ bits per byte per doubling, the constant the bound below uses. The document
reading of Section~\ref{sec:protocol} scores up to $2{,}048$ tokens of context.

\paragraph{Token-aligned blocks: a small bias, bounded.} Evaluation blocks are 512 \emph{tokens}
rather than a fixed byte span, so models with different tokenizers score slightly different amounts
of text: 5.92--6.24\,MB across the eleven-model cohort, a $5\%$ spread, and $9.9\%$ across the
seventeen. Bounding the resulting bias with the measured context sensitivity puts it at $0.08\times$
the smallest adjacent rank gap in the eleven-model cohort. In the extended cohort the worst ratio of
bound to gap is $0.61$, for Qwen2.5-3B over Falcon3-7B; the bound overturns no rank. The document
reading covers identical bytes for every model and removes the question.

\paragraph{Seed variation is negligible.} The published adaptation cells did not fix the \texttt{torch} random
seed, which sets the LoRA initialisation, dropout and batch order (the data splits are seeded
separately). A check fixed before it ran re-ran all $17$ news models with three explicit seeds ($51$
cells, everything else pinned). The median within-model standard deviation of adapted BPB is
$0.0001$ against a between-model standard deviation of $0.074$, and none of the $40$ pairs of models
within $2\times$ in size reverses its order across seeds. Gemma-4-12B is the one model where seed
noise is visible (standard deviation $0.003$, five times the next largest).

\paragraph{The mathematics shift.} Adapting on general text raises agreement with HellaSwag on news
from $\rho = 0.718$ to $0.982$ while GSM8K falls from $0.800$ to $0.700$ and MMLU-Pro from $0.845$ to
$0.773$; adapting on arXiv mathematics raises GSM8K agreement to $0.909$ and recovers GSM8K's top
model, while the three general-text corpora all leave GSM8K at or below its unadapted agreement. The
shift predicts a \emph{joint} movement, so we test it with a difference in differences: (GSM8K minus
HellaSwag selection accuracy under mathematics adaptation) minus the same quantity under a
general-text corpus, which is $+0.242$ pooled. Resampling models gives a strictly positive difference
in $93.7\%$ of draws (one-sided $p \approx 0.06$). Resampling whole publisher families, which the
shared training data of a family calls for, gives $80.9\%$ ($p \approx 0.19$), with ties counted as
non-positive; not one of its $20{,}000$ draws is negative. A leave-one-family-out jackknife shows the
dependence: dropping the two Gemma models takes the pooled difference from $+0.242$ to $+0.056$.
More families, rather than more models, would settle it.

\paragraph{Reproduction controls.} Re-running two Ministral-3-14B cells weeks later on different
hardware reproduced unadapted BPB exactly and adapted BPB to within $0.0003$. Because the six added
models were adapted on a different software stack, a published cell (Qwen2.5-7B) was re-run through
that stack; the cohorts are pooled only because it reproduces within $1\%$, and it reproduces to
$0.01\%$ on adapted BPB ($0.7169$ against $0.7170$).

\section{The Downstream Fine-Tune}
\label{sec:downstream}
Section~\ref{sec:divergence} reports the result; this section describes how it was built. It ran in
two stages, each fixed in code before its job returned: first the two pairs on which the rankings
disagree most (Gemma-4-12B against Ministral-3-14B, Llama-3.2-1B against Qwen-2.5-1.5B), then every
cohort model that fits one GPU, so that no pair is hand-picked. Gemma-4-31B and Qwen-3.5-35B-MoE need
more than one GPU for this fine-tune, because its $1{,}280$-token sequences and its generation pass
cost far more memory than the $512$-token adaptation (Appendix~\ref{app:readings}), and are excluded by
that rule, which costs one size-matched pair of forty. The fine-tuned scores, pairs and rankings
are released.\artifact{results/downstream.json}

\paragraph{The task.} Journalistic convention makes a news article's first paragraph a standalone
summary of it, so the corpus supplies its own supervision: the input is the article with its opening
paragraph removed, truncated to $3{,}000$ characters, and the target is that paragraph. Articles
qualify if they have at least three paragraphs, an opening paragraph of $200$--$700$ characters
ending in sentence punctuation, and at least $800$ characters of remaining body. Of the $11{,}905$
validation documents, $3{,}627$ qualify; $2{,}000$ are sampled for training and $500$ for evaluation
under a fixed seed.

\paragraph{Why the validation split.} The BPB test blocks live in the \emph{test} split, so the
fine-tuning task is built from the validation split instead. Evaluation documents are hashed against
the test documents twice, on full normalised text and on a $400$-character opening, the second
because a syndicated wire story is republished with an edited body and an identical lede. Four
candidate articles were dropped by that second check, before the $500$ were sampled, and none by the
first.

\paragraph{Equal preparation.} Every model gets the adaptation recipe unchanged (LoRA rank $16$,
$\alpha{=}32$, dropout $0.05$, learning rate $10^{-4}$, effective batch $32$, $250$ steps), starting
from its base weights, with prompt tokens masked out of the loss so the model is trained to write
the lede rather than to reconstruct the article. The tokenizers differ, so the budget is matched in
update steps $\times$ batch $\times$ sequence length; each model's realised token count is in the
artifact. Decoding is greedy with a $180$-token cap and each checkpoint's own generation
configuration otherwise untouched, following Appendix~\ref{app:rescore}. The prompt is plain text:
the article body followed by an instruction to write its opening paragraph. When the prompt is too
long, the body is cut, never the instruction after it, because cutting the assembled prompt would
delete the instruction from the longest articles, at a different article count for each tokenizer.
At most four of the $500$ evaluation articles were cut for any model, and none for three of them.

\paragraph{The decision rules, fixed before each run.} For the two chosen pairs: mean ROUGE-L F1
over the $500$ held-out articles, a paired bootstrap over articles ($20{,}000$ draws, $95\%$ percentile
interval) and a practical-equivalence margin of $0.01$; an interval excluding zero resolves the pair
for whichever ranking predicted that winner. The first pair resolved for adapted BPB; the second was
inconclusive. For the full cohort the fine-tuned ROUGE-L is the outcome, and every ranking is scored
by pairwise accuracy within $2\times$ with a model-level bootstrap of $20{,}000$ draws
(Table~\ref{tab:downstream}). A separate guard voids any comparison in which fine-tuning failed to
improve a model over its own base weights, since ordering unmoved models would order their base
behaviour under another name. It did not fire: all fifteen models gained between $+0.041$ and
$+0.153$.

\paragraph{A second recipe.} Recipe B changes every setting the adaptation and the fine-tune shared
(LoRA rank $64$, $\alpha{=}128$, learning rate $3\times10^{-4}$, effective batch $16$, $400$ steps, a
new seed) on the same task, data, decoding and metric, and was fixed before it ran. It fits the
training articles far harder and scores slightly below recipe A for every model, yet orders the
fifteen systems almost identically (Spearman $0.982$). Against recipe-B systems adapted block BPB,
and document BPB with the same order, remain the top ranking at $0.923$ $[0.750, 1.000]$, ahead of HellaSwag at $0.846$, parameter count at $0.744$
and GSM8K and MMLU-Pro near chance, and it picks the better system on all $20$ pairs recipe B
resolves. Its margin over parameter count, resolved under recipe A, does not resolve here ($+0.179$
$[-0.036, +0.441]$), so that margin is recipe-specific (Table~\ref{tab:downstream}).

\paragraph{What copying scores.} A news body restates its own lede, so reference overlap is partly
available by copying. The article's first body sentence scores $0.125$ against the reference and a
random body sentence $0.111$. Unadapted base weights land close to copying (inspection confirms they
largely do copy), while every fine-tuned system clears it, from $0.188$ (Qwen-2.5-0.5B) to $0.249$
(Gemma-4-12B).

\paragraph{How close the corpus has to be.} Exploratory, run after the result: on the ten
size-matched pairs of the nine fine-tuned models adapted on all four corpora, adapted BPB orders the
news fine-tune with pairwise accuracy $0.900$ for news and for Reddit, $0.700$ for Hacker News and
$0.600$ for arXiv mathematics; the unadapted block readings reach $0.500$--$0.600$. Ten pairs support no interval, so this is a direction, not a result. The unadapted document reading on all fifteen models and $39$ pairs is in Table~\ref{tab:downstream}.

\section{The Benchmark Re-Score}
\label{app:rescore}
\paragraph{Harness configuration.} MMLU-Pro is 5-shot chain-of-thought with exact match on one
stratified $1{,}000$-question subset (seed 42); HellaSwag is 10-shot length-normalised
multiple-choice accuracy on all $10{,}042$ validation examples; GSM8K is 5-shot chain-of-thought with
flexible numeric extraction on all $1{,}319$ test examples. All bf16, greedy, with each tokenizer's
own beginning-of-sequence token. The raw harness logs for all three
benchmarks are released.\artifact{results}

\paragraph{One host.} Generative scores do not pool across hosts: identical released weights move
$-0.60$ to $+0.69$ GSM8K points when only the GPU changes from A100 to H100. The benchmark columns were therefore scored again in full on one host
(A100-SXM-64GB) with one software build: seventeen models $\times$ three benchmarks $=$ fifty-one
cells, with the design and the exclusion rule fixed in advance. The task definitions match the
earlier scoring exactly (identical task hashes for all seventeen models on GSM8K and HellaSwag; MMLU-Pro ships none), and
every overlapping cell agrees with it to within $1.3$ points, most to within $0.3$.

\paragraph{Decoding settings.} The newer harness honours each checkpoint's shipped
\texttt{generation\_config.json}, and the earlier one did not. Replacing every checkpoint's
generation settings with one identical policy also discarded \texttt{suppress\_tokens}, which is set
for Gemma-4-12B; that omission cost it $9.86$ GSM8K and $14.30$ MMLU-Pro points, while HellaSwag,
scored by likelihood, was unchanged. Keeping each checkpoint's own settings for all seventeen models
reproduces the earlier scoring for Gemma-4-12B to within $+1.21$ points on GSM8K, $+0.10$ on MMLU-Pro
and $-0.27$ on HellaSwag. The GSM8K cell is the one outside the $1.0$-point tolerance fixed in
advance, within the allowance of one such cell.
